# LocalMiniDrama（本地短剧助手）操作文档

> 版本：对应 backend v1.2.8 / front-user v1.2.8 / front-admin v1.0.0
> 更新日期：2026-08-12
> 数据存储：**统一使用本地 MySQL 8**（库名 `localminidrama`），无 mock、不与 SQLite 混用。SQLite（`better-sqlite3`）仅用于单元测试的内存库，不参与任何实际运行/存储。

---

## 一、系统概览

本产品为一款 AI 驱动的本地短剧（漫剧）创作平台，采用「一个产品、三个子工程、单仓库（npm workspaces）」结构：

| 服务 | 目录 | 端口 | 说明 |
|------|------|------|------|
| 后端 API（Express + MySQL + Socket.io） | `backend-node/` | **5679** | 提供 REST API（`/api/v1`）、静态资源（`/static`）、实时协作（`/socket.io`），并在生产模式下托管用户端构建产物 |
| 用户端前端（Vite + Vue 3） | `front-user/` | **3013** | 面向创作者的一站式创作工作台 |
| 管理后台前端（Vite + Vue 3 + Element Plus） | `front-admin/` | **3014** | 面向运营/管理员的后台管理系统 |

- 两个前端在开发模式下均通过 Vite 代理，将 `/api` 与 `/static` 请求转发到后端 `http://127.0.0.1:5679`。
- 共享代码位于 `packages/shared/`（`@localmini/shared`）。
- 纯 JavaScript 实现（无 TypeScript）。

### 前置依赖

| 依赖 | 版本 | 用途 | 是否必需 |
|------|------|------|---------|
| Node.js | ≥ 18 | 运行时 | ✅ 必需 |
| MySQL | 8.x | 唯一数据存储（`localminidrama` 库，账号 `root/root`，端口 `3306`） | ✅ 必需 |
| Redis | 6+ | Bull 异步任务队列（长文本/批量生成） | ⭕ 可选（未启动时自动降级为内存队列） |
| AI 服务 API Key | — | 文本/图片/视频/语音生成 | ⭕ 可选（无 Key 时创作类 AI 功能不可用，但系统可正常启动与浏览） |

> 配置文件：`backend-node/configs/config.yaml`（已随仓库提供，`database.type: mysql`）。首次使用无需额外拷贝。

## 二、服务启停命令

> 以下命令均在**项目根目录** `LocalMiniDrama_web/` 下执行；后端命令需进入 `backend-node/`。

### 2.1 首次准备（仅第一次）

```bash
# 1. 确认 MySQL 已启动，并已创建库 localminidrama（账号 root/root）
mysql -uroot -proot -e "CREATE DATABASE IF NOT EXISTS localminidrama CHARACTER SET utf8mb4;"

# 2. 安装依赖（根目录一次性安装 workspaces + 后端依赖）
npm install
cd backend-node && npm install && cd ..

# 3.（可选）首次初始化数据库表结构。正常启动时会自动执行迁移，此步一般可跳过
cd backend-node && npm run migrate && cd ..
```

> 说明：后端启动时会自动执行数据库迁移（`runMigrationsAndEnsure`）并初始化默认管理员账号，无需手动建表。

### 2.2 启动服务

**后端（端口 5679）**

```bash
cd backend-node
npm run dev      # 开发模式：node --watch 热重载，改代码自动重启
# 或
npm start        # 生产模式：node src/server.js（无热重载）
```

启动成功后日志会打印：
```
Server starting { port: 5679, host: '0.0.0.0' }
API:    http://localhost:5679/api/v1
Health: http://localhost:5679/health
Server is ready!
```
后端启动时自动完成：① 执行数据库迁移；② 初始化默认管理员（`admin` / `admin123`）；③ 挂载 Socket.io 实时协作网关（复用 5679 端口）。

**用户端前端（端口 3013）**

```bash
npm run dev:user
# 访问 http://localhost:3013
```

**管理后台前端（端口 3014）**

```bash
npm run dev:admin
# 访问 http://localhost:3014
```

**一键同时启动两个前端**

```bash
npm run dev:all   # 使用 concurrently 并行启动 user + admin
```

> 完整启动顺序建议：先启动 MySQL →（可选 Redis）→ 后端 → 前端。

### 2.3 停止服务

- **前台运行时**：在对应终端窗口按 `Ctrl + C`。后端已实现优雅关闭（SIGINT/SIGTERM），会先断开所有协作 socket、关闭 HTTP 服务与数据库连接后退出（5 秒超时强制退出）。
- **按端口查杀（后台/僵死进程）**：

```bash
# 停止后端 5679
lsof -ti :5679 | xargs kill

# 停止用户端 3013 / 管理端 3014
lsof -ti :3013 | xargs kill
lsof -ti :3014 | xargs kill
```

### 2.4 构建与部署

```bash
# 构建两个前端产物（dist/）
npm run build:all
# 或分别构建
npm run build:user    # 输出 front-user/dist
npm run build:admin   # 输出 front-admin/dist
```

> 生产模式下，当 `front-user/dist/` 存在时，后端会在 `5679` 端口直接托管用户端产物；开发阶段请仍使用 Vite 开发服务器（3013 / 3014）。

### 2.5 常用运维命令（后端 `backend-node/`）

```bash
npm test                     # 运行全部单元测试（node --test test/*.test.js）
npm run test:coverage        # 覆盖率报告（文本）
npm run migrate              # 手动执行数据库迁移
npm run alert:scan           # 数据异常/负余额告警扫描（一次性）
npm run alert:cron:install   # 安装定时告警扫描 crontab
npm run alert:cron:status    # 查看定时任务状态
```

### 2.6 健康检查

```bash
curl http://localhost:5679/health          # 后端健康状态
curl http://localhost:5679/api/v1/docs     # Swagger API 文档（浏览器打开）
```

## 三、管理员使用指南（管理后台，端口 3014）

### 3.1 登录

1. 浏览器访问 `http://localhost:3014`。
2. 使用默认超级管理员账号登录：

   | 账号 | 密码 | 角色 |
   |------|------|------|
   | `admin` | `admin123` | `super_admin`（超级管理员） |

   > 该账号由后端启动时的 `initAdmin` 自动创建/校准。**首次登录后请尽快在「系统管理 → 管理员管理」中修改密码。**
3. 登录后默认进入「首页 · 运营概览」。仅 `super_admin`/管理员角色可进入后台，普通用户会被拦回登录页。

### 3.2 功能菜单总览

管理后台按业务域分组，主要模块如下（对应前端路由）：

**① 运营概览**
- 首页 Dashboard（`/dashboard`）：实时指标卡片、创作漏斗、模型成本洞察、AI 监控面板。

**② 模型网关（AI 能力管理）**
- 模型配置（`/model-gateway/model-config`）：配置各家文本/图片/视频/语音模型与 Key。
- 渠道列表（`/model-gateway/channel-list`）：AI 供应商渠道管理。
- 请求记录（`/model-gateway/request-logs`）：AI 调用日志（成功率/耗时/成本）。
- 任务队列（`/model-gateway/task-queue`）：异步生成任务的进度与状态。

**③ 用户与团队**
- 用户管理（`/user-team/users`）：创建/编辑/禁用用户、调整角色。
- 团队管理（`/user-team/teams`）：团队/企业成员编排。
- 渠道管理（`/user-team/channels`）：注册来源渠道。
- **用户生命周期（`/user-team/lifecycle`）**（S12-T04）：用户画像、健康分、生命周期阶段（new/active/paying/at_risk/churned）、流失预警。

**④ 内容与资产**
- 作品管理（`/content-asset/works`）：平台全部短剧项目。
- 技能管理、公共资产/工具库、真人库。
- 模板管理（`/content-asset/templates`）（S6）：题材模板 CRUD 与预览。
- **存储对象管理（`/content-asset/storage-objects`）**（S12-T03）：对象存储台账、生命周期扫描。
- **素材标签库（`/content-asset/material-tags`）**（S12-T01）：五维度智能标签词典与统计。

**⑤ 运营工具**
- 站点品牌、版本日志、短信配置、TOS 配置、协议管理。
- 用户问题排查、日志检索。
- 告警通道 / 告警历史 / 数据异常检测。
- **数据分析平台（`/operation/data-analytics`）**（S12-T08）：用户行为分析、创作漏斗、模型效果、留存分析（cohort d1/d7/d30）。

**⑥ 财务与计费**
- **收支总览（`/finance/overview`）**（S12-T05）：实时成本核算、收入、毛利/毛利率/ARPU、欠费预警。
- 充值套餐、优惠券管理、支付配置、支付订单。
- 全局计费设置（`/finance/global-billing`）：业务类型 × 用户等级的计费规则。

**⑦ 系统管理**
- 管理员管理、角色管理、菜单管理、字典管理、参数设置、通知公告。
- **操作日志（`/system/operation-logs`）**（S12-T07）：操作审计（含数据脱敏、字段级权限）。
- **登录日志（`/system/login-logs`）**（S12-T07）：登录明细与统计。
- **系统监控大屏（`/system/monitor`）**（S12-T06）：CPU/内存/磁盘/API/队列实时监控（ECharts 曲线）。

### 3.3 典型管理任务

- **新建用户**：用户与团队 → 用户管理 → 新建，填写用户名/密码/角色（`user`/管理员）。
- **配置 AI 模型**：模型网关 → 模型配置，填入供应商 Key 后即可启用创作类 AI 能力。
- **处理欠费用户**：财务 → 收支总览查看欠费预警；系统通过 `platform_notifications` 表向欠费用户发送站内通知，并对 AI 创作入口做余额守卫（`super_admin` 豁免）。
- **排查异常**：运营工具 → 数据异常检测 / 日志检索；或后端执行 `npm run alert:scan`。

## 四、普通用户使用指南（用户端，端口 3013）

### 4.1 注册与登录

1. 浏览器访问 `http://localhost:3013`。
2. **注册**（`/register`）：使用**手机号 + 密码**（手机号需为有效 11 位；密码至少 6 位）。注册成功即以普通用户（`role: user`）身份登录，用户名默认为手机号。
3. **登录**（`/login`）：使用手机号（或用户名）+ 密码登录。登录态基于 JWT，有效期 7 天。

### 4.2 核心创作流程（一站式工作台）

推荐主路径：**项目列表 → 新建项目 → 一站式创作工作台**。

1. **项目列表**（`/dashboard`）：查看/新建短剧项目。
2. **AI 编剧助手**（`/screenwriter`）：输入一句话创意 → 生成三幕式大纲 → 角色档案 → 分集剧情 → 分镜脚本 → 台词，可逐段修改重生成，并一键创建完整项目。
3. **一站式创作工作台**（`/film/:id/workbench`）：三栏布局——
   - 左侧：项目导航树（剧本/角色/场景/道具/分镜/音频/导出）。
   - 中间：无限画布（多层级缩放、小地图、分区、搜索、书签、标注），可直接编辑角色/场景/分镜。
   - 右侧：AI 助手面板（AI 编剧 / AI 分镜 / AI 配音 / AI 优化）+ 生成队列进度。
   - 底部：分镜时间轴（拖拽排序、缩略图预览）。
   - 支持多人实时协作（角色分工 + 节点锁 + 版本快照/回退）。
4. **画布模式**（`/film/:id/canvas`）与 **剧集管理**（`/drama/:id`）：更聚焦的编辑视图。
5. **角色详情**（`/character/:id`）：查看角色一致性分数（低于阈值标红），支持编辑人设/外貌。

### 4.3 独立创作工具（`/tools/*`）

用户端提供一组独立小工具，可脱离项目直接使用：

| 工具 | 路径 | 说明 |
|------|------|------|
| 图片生成 | `/tools/image-generate` | 文生图 / 参考图注入 |
| 视频生成 | `/tools/video-generate` | 文/图生视频 |
| 音频生成 | `/tools/audio-generate` | TTS 配音 |
| 音频成对 | `/tools/audio-pair` | 台词与音色配对 |
| 文字对话 | `/tools/text-chat` | AI 文本对话 |
| 提示词优化 | `/tools/prompt-optimize` | 优化生成提示词 |
| 剧情拆分 | `/tools/plot-split` | 长剧情自动拆分 |
| 反推视频 / 去字幕 / 视频超分 | `/tools/video-*` | 视频后处理 |

其他：**自由创作**（`/free-create`）、**媒体素材库**（`/media-library`）、**AI 配置**（`/ai-config`，用户可自配 AI Key）。

### 4.4 使用须知

- 创作类 AI 功能（生成图片/视频/配音等）需先在「AI 配置」或由管理员在后台配置有效的 AI API Key。
- **积分与欠费**：平台以「100 积分 = 1 元」计费。当账户余额不足/欠费时，AI 创作入口会被暂停（返回 403 提示），并收到站内欠费通知，充值后恢复。
- 所有创作数据（项目/角色/分镜/素材/生成记录等）均存储在服务端 MySQL，不使用本地 mock 数据。

## 五、数据存储说明（重要）

- **唯一数据源为本地 MySQL**：`backend-node/configs/config.yaml` 中 `database.type: mysql`，连接 `localhost:3306` 的 `localminidrama` 库（账号 `root/root`）。所有业务数据、测试数据均落地此库。
- **不使用 mock 数据**：种子脚本（`backend-node/scripts/seed_*.js`）与测试用例均向真实 MySQL 写入并在结束后清理，使用高位测试 ID 隔离，不污染业务数据。
- **不混用 SQLite**：`better-sqlite3` 仅作为单元测试的内存库依赖存在（`node --test`），不参与任何实际运行或数据落地。代码中所有 MySQL 专用语法均已按 `db.type` 做双库分支，仅为保证测试可运行，生产/开发一律走 MySQL。
- **迁移**：位于 `backend-node/migrations/`（当前最高编号 48），后端启动时自动按文件名顺序执行；也可手动 `npm run migrate`。

## 六、常见问题（FAQ）

| 现象 | 排查 |
|------|------|
| 前端页面报 `ECONNREFUSED 127.0.0.1:5679` | 后端未启动或已退出，重新 `cd backend-node && npm run dev` |
| 后端启动报数据库连接错误 | 确认 MySQL 已启动、`localminidrama` 库存在、账号 `root/root` 正确 |
| AI 生成无反应/报错 | 未配置有效 AI Key，前往「AI 配置」或后台「模型配置」填入 |
| 队列任务不消费 | Redis 未启动（可选依赖）；未启动时会降级为内存队列，重启后任务不持久 |
| 管理后台无法登录 | 使用默认 `admin` / `admin123`；若被改动，可重启后端触发 `initAdmin` 重置为该账号密码 |
| 忘记普通用户密码 | 由管理员在后台「用户管理」中重置 |
| 端口被占用 | `lsof -ti :端口 | xargs kill` 释放后重启 |
