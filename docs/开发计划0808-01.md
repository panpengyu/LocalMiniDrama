## 一、计划总览

### 1.1 阶段划分

| 阶段 | 时间窗口 | Sprint范围 | 核心目标 | 预期产出 |
|------|---------|-----------|---------|---------|
| **第一阶段** | 第1-2月 | S1-S4 | 核心智能化 | AI编剧+角色一致性+一站式工作台+后台运营基础 |

## 二、第一阶段：核心智能化（S1-S4）

### Sprint 1: 基础设施升级 + AI编剧助手（后端）

**Sprint目标**: 搭建任务队列基础设施，实现AI编剧助手核心后端能力

#### 任务清单

| 编号 | 任务 | 类型 | 预估 | 依赖 | 验收标准 |
|------|------|------|------|------|---------|
| S1-T01 | 集成 Redis + Bull 任务队列 | 后端/基建 | 1d | 无 | Redis连接正常，Bull队列可创建/消费任务 |
| S1-T02 | 设计 AI编剧服务架构 | 后端 | 1d | 无 | 确定提示词模板、输出结构、多轮对话方案 |
| S1-T03 | 实现剧本大纲生成接口 | 后端 | 2d | S1-T02 | `POST /api/v1/ai/screenwriter/outline` 输入一句话创意，返回三幕式大纲 |
| S1-T04 | 实现角色档案自动生成 | 后端 | 2d | S1-T03 | `POST /api/v1/ai/screenwriter/characters` 根据大纲生成主角/配角/反派档案 |

| S1-T07 | 实现对话台词生成接口 | 后端 | 2d | S1-T04 | `POST /api/v1/ai/screenwriter/dialogue` 根据角色+场景生成台词 |

**Sprint交付物**:
- Redis + Bull 任务队列运行环境
- AI编剧助手5个核心API接口
- 数据库 `drama_templates` 表及种子数据

**风险与对策**:
- 风险: AI大模型生成质量不稳定 → 对策: 提示词工程优化 + 结构化输出约束(JSON Schema)
- 风险: 大模型响应时间长 → 对策: 异步任务队列 + 前端轮询/WebSocket进度推送
