### 1. `useCanvasVirtualization.js` — 画布虚拟化
- 签名：`useCanvasVirtualization(nodes, viewport, containerSize, options)`，三者均为 ref 以保证响应式
- AABB 相交剔除：屏幕坐标 = 世界坐标 × zoom + translate，视口外扩 `bufferSize`(默认 200px)
- 节点坐标兼容 `x/y` 与 VueFlow 的 `position.x/position.y`，尺寸兼容 `width/height` 与 `data.width`
- 节点总数 > `threshold`(默认 100) 时 `isEnabled` 自动置 true；剔除结果为空时回退全量渲染，防异常空白
- 返回 `visibleNodes`、`hiddenCount`、`isEnabled`（均为 computed/ref）
- 与现有 `useCanvasViewportVirtualization.js`（VueFlow 专用）互补，不冲突

### 2. `useRAFThrottle.js` — RAF 节流
- `rafThrottle(fn)`：每个包装函数拥有独立 pending 状态，同帧多次调用只执行最后一次
- `useRAFValue(initial)`：返回 `{ value, set }`，`set` 经 RAF 节流更新
- `cancelAll()`：统一取消所有待执行 RAF id（用 Set 跟踪）
- `onScopeDispose` 自动清理（已用 `getCurrentScope()` 守卫，非组件作用域下不警告）
- 额外修复了一处清理顺序瑕疵：回调内先捕获真实 id 再置空，确保从 Set 正确移除

### 3. `useLazyImage.js` — 图片懒加载
- 共享单个 `IntersectionObserver`，`rootMargin: 200px` 提前触发加载
- `createLazyImageRef(src, placeholder)` 返回 `{ isVisible, currentSrc, error, setRef }`，`setRef` 绑定到模板 `:ref`
- 默认灰色占位符 + 加载失败红色"加载失败"占位符（运行时 `encodeURIComponent` 生成 SVG data URI，兼容中文）
- 进入视口后用 `new Image()` 预加载，成功替换 `currentSrc`，失败置错误占位符
- `onScopeDispose` 自动 `disconnect` observer

### 4. `usePerformanceMonitor.js` — 性能监控
- RAF 每秒结算一次 `fps`；`nodeCount`、`renderTime` 为可写 ref 供调用方写入
- `shouldDegrade`（computed）：`fps > 0 && fps < 30` 时为 true；`isDegrading`（ref）同步标记并打印降级告警
- `logMetrics(tag?)` 打印 fps/节点数/渲染耗时/降级状态
- 默认自动启动，返回 `start`/`stop` 供手动控制；`onScopeDispose` 自动停止循环

## 关键设计决策
- **清理钩子选用 `onScopeDispose`**（而非 `onUnmounted`）：这是 Vue 3 对可复用 composable 的推荐做法，在组件卸载时同样触发，且在独立 `effectScope` 中也能正确清理。均用 `getCurrentScope()` 守卫，避免在非作用域上下文调用时产生警告。
- **虚拟化入参用 ref**：使 `visibleNodes` 成为 computed，无需手动触发重算，视口/节点/容器任一变化自动响应。
- **降级标记同时提供 computed 与 ref**：`shouldDegrade`(computed) 适合模板/派生计算，`isDegrading`(ref) 适合 `watch` 触发副作用。

### 四、修复运行时发现的**致命Bug**：新建Drama被Bloom误判404
