# 未完成功能清单（对比《高端智能漫剧创作平台》需求）

> 生成日期：2026-08-16
> 对比基线：`docs/高端智能漫剧创作平台.md`（需求） vs 当前代码（`main` 分支，v1.5.0，Sprint 1-16 已交付）
> 检查方式：全量代码走查（backend-node / front-user / front-admin / packages），重点核查需求文档 8 大板块、30+ 功能点的实现深度（完整 / 部分 / 骨架 / 未实现）。

## 一、总体结论

需求文档中定义的 8 大板块（智能引擎 / 创作工作流 / 协作生态 / 素材管理 / 视频后期 / 平台基建 / 后台管理 / 商业化）经核对：

- **约 80% 功能点已完整落地**，具备可用闭环（见文末"已满足需求概览"）。
- **12 项功能完全缺失**（代码中无对应实现，含分支叙事、报表订阅、A/B 测试、2FA 等）。
- **25 个管理端页面为占位骨架**（约 361 字节的模板页，无真实业务逻辑）。
- **7 项功能部分实现**（有基础能力，缺关键环节，如 LoRA 训练仅文案、支付宝 SDK 未接入、任务队列未用 Bull/Redis 等）。

**优先级定义**：P0 = 直接影响核心体验/商业化闭环/合规；P1 = 重要能力缺失，影响运营或高级卖点；P2 = 增强完善类。

## 二、完全缺失的功能（需求已定义，代码中无实现）

### P0-1 分支叙事支持（4.2.4 无限画布）
- **需求描述**：支持分支叙事（用户标记"此处开启分支"），分镜节点带分支标记、条件连线可视化、支持按分支导出一部短剧。
- **当前现状**：
  - `front-user/src`：无分支标记、无条件连线交互（`search branch` 仅命中无关 UI 文案）。
  - `backend-node`：canvas/节点/剧本数据模型无 `branch_*` 字段，无分支导出接口。
- **差距**：数据模型 + 画布交互 + 导出链路三层均缺失。
- **建议方案**：分镜表增加 `branch_id/branch_type` 字段 → 画布增加分支标记与条件连线 → 剧本/成片导出支持按分支切分。

### P0-2 语音评论（5.3 评论批注）
- **需求描述**：支持文字评论与语音评论。
- **当前现状**：`backend-node/src/routes/comments.js` 仅文字评论，无 `audio_url` 字段；前端无录音组件。
- **差距**：后端字段 + 文件上传 + 前端录音 UI 均缺失。
- **建议方案**：评论表加 `type(1文字/2语音)`、`audio_url`、`audio_duration` → 前端评论面板加录音按钮（MediaRecorder）→ 后端复用 `/static` 上传能力。

### P0-3 管理端财务页占位（9.5 财务与计费增强）
- **需求描述**：充值套餐、优惠券、支付配置、支付订单、全局计费五个页面的管理能力。
- **当前现状**：`front-admin/src/views/finance/` 下仅 `Overview.vue`（18KB，真实）真实，其余 5 个页面均为 361 字节占位骨架：
  - `RechargePlans.vue`、`Coupons.vue`、`PaymentConfig.vue`、`PaymentOrders.vue`、`GlobalBilling.vue`
- **差距**：后端 `finance.js` 已有部分接口（余额/账单/欠费闭环/日报），但充值套餐、优惠券、支付配置、支付订单的**前端界面及部分后端接口缺失**，会员充值链路无法在管理端运营。
- **建议方案**：按"套餐 CRUD → 优惠券 CRUD → 支付配置 → 支付订单查询 → 全局计费汇总"顺序补齐。

### P1-4 报表订阅（9.1 智能运营看板）
- **需求描述**：日报/周报/月报自动生成并发送至邮箱/钉钉（Webhook）。
- **当前现状**：`finance.js` 有 `daily-report`（财务日报生成/查询）接口，但**无订阅配置、无定时任务、无邮件/钉钉推送**；`front-admin` 无订阅管理界面。
- **差距**：缺少"订阅规则表 + cron 定时生成 + 推送渠道适配（邮箱/钉钉 webhook）+ 管理界面"。
- **建议方案**：新增 `report_subscription` 表 + `reportJobService.js`（node-cron）+ `notifyService.js` 邮件/钉钉适配。

### P1-5 自定义仪表盘（9.1 智能运营看板）
- **需求描述**：管理员可拖拽配置自己的看板布局。
- **当前现状**：`Dashboard.vue` 为固定布局，无拖拽配置；无 `dashboard_config` 持久化。
- **建议方案**：`dashboard_layout` 表存储组件配置 → 前端引入 vuedraggable 实现组件拖拽 → 按管理员维度持久化。

### P1-6 A/B 测试（9.2 AI 模型管理中枢）
- **需求描述**：同一任务并行调用多个模型，对比生成效果，依据结果动态调整路由权重。
- **当前现状**：`modelRoutingService.js` 已实现智能路由、熔断、评分（成功率40%+速度30%+质量30%），但**无 A/B 测试模式**（无并行调用、无对比报告）。
- **建议方案**：路由层增加 `abTest` 配置（命中比例/并行调用/结果对比/权重自动调整），前端增加 A/B 测试管理页。

### P1-7 模型用量配额管理（9.2 AI 模型管理中枢）
- **需求描述**：按用户/团队/企业设置模型使用配额。
- **当前现状**：`quotaService.js` 仅实现会员四类配额（generation/project/storage/collaborator），**无模型级用量配额**（按 token/按模型配置）。
- **建议方案**：`model_usage_quota` 表（user/team/enterprise × model）→ `modelRoutingService` 前置配额校验。

### P1-8 版权检测（9.3 内容审核系统）
- **需求描述**：与公共素材库比对，检测用户上传素材的侵权风险。
- **当前现状**：审核系统已实现 AI 图文视频审核、人工复审、规则配置、拦截通知、申诉，但**无版权比对**。
- **建议方案**：素材上传时计算感知哈希（pHash），与公共素材库指纹表比对，超阈值标记侵权。

### P1-9 自动扩缩容（9.6 系统监控与运维）
- **需求描述**：基于负载自动扩缩容。
- **当前现状**：`Monitor.vue` + `systemMonitorService.js` 已实现健康大屏/API 监控/队列监控/告警，但**无扩缩容**。
- **建议方案**：接入 PM2 cluster 或 Docker/K8s 编排，监控模块输出扩容建议指标（CPU/队列积压）。

### P1-10 运维自动化（9.6 系统监控与运维）
- **需求描述**：一键部署/回滚/备份/恢复。
- **当前现状**：无任何部署自动化能力（仅 `deploy/` 下的 Nginx 配置与 SQL 脚本）。
- **建议方案**：新增 `deploy/opsScripts/`（备份/恢复脚本）、`OpsCenter.vue` 管理页（备份任务、一键回滚按钮）。

### P1-11 安全策略（9.7 权限与安全增强）
- **需求描述**：密码策略、登录限制、IP 白名单、双因素认证（2FA）。
- **当前现状**：
  - `apiKeyService.js` 仅有 API Key 的 IP 白名单；
  - **管理员/用户登录侧无**密码强度策略、失败锁定、登录 IP 白名单、2FA（TOTP）。
- **建议方案**：`securityPolicy` 配置表 → 登录中间件校验（密码复杂度/尝试锁定/IP 白名单/TOTP 验证码）→ 管理端安全策略配置页。

### P1-12 会话管理（9.7 权限与安全增强）
- **需求描述**：在线会话查看、强制下线。
- **当前现状**：`routes/security.js` 无 session 接口；前端无会话管理页。
- **建议方案**：基于 token 的 session 表（`session_id/user_id/login_ip/expire`）→ 管理端在线会话列表 + 强制下线接口（吊销 token）。

### P1-13 事件埋点服务（8.3 数据分析）
- **需求描述**：统一事件埋点（行为埋点、上报、清洗）。
- **当前现状**：`analyticsService.js` 无 track/埋点相关实现（全部依赖现有业务统计表）。
- **差距**：缺少用户行为轨迹埋点采集（进入创作页/生成成功/付费转化等），留存分析、漏斗分析依赖埋点数据。
- **建议方案**：新增 `tracking_events` 表 + `trackingService.js`（collect/batch/聚合），前端 `tracking.js` 统一埋点 SDK，前端路由/关键操作自动上报。

### P1-14 数据导出 / 自定义报表（8.3 数据分析）
- **需求描述**：自定义报表、数据导出。
- **当前现状**：`routes/analytics.js` 无 export 接口；`DataAnalytics.vue` 仅图表展示。
- **建议方案**：统计接口支持 `?export=csv`（或 xlsx），前端加"导出"按钮。

### P1-15 支付宝支付真实接入（10.1 会员体系）
- **需求描述**：支持微信/支付宝支付订阅会员。
- **当前现状**：
  - 微信支付 v3 已真实接入（验签+AES-256-GCM 解密、订单创建/支付/自动续费/关单）；
  - **支付宝仅预留验签接入点，`verifyAlipaySignature` 恒返回 false（SDK 未接入）**。
- **建议方案**：引入 `alipay-sdk`，实现验签与回调处理，配置页补充支付宝参数。

### P2-16 智能剪辑前端操作界面（7.1 智能剪辑）
- **需求描述**：节奏优化、画面调色、字幕生成、水印添加。
- **当前现状**：
  - 后端已实现：自动剪辑、智能转场（`transitionEffects.js`）、节奏匹配、字幕生成、水印、调色能力（`videoService.js` / `mergedEpisodePostProcess.js`）；
  - 前端 `SmartEditTimeline.vue` 仅有分辨率/帧率/转场/节奏/配音对齐选项，**无字幕、水印、调色的可视化设置面板**。
- **建议方案**：`SmartEditTimeline.vue` 扩展字幕（文本/样式/多语言）、水印（图片/位置/透明度）、调色（滤镜/亮度/对比度）设置项，联动后端参数。

### P2-17 音效智能匹配（3.4 智能配音）
- **需求描述**：音效智能匹配（爆炸/脚步/环境音等）。
- **当前现状**：`bgmService.js` 已实现 BGM 情绪匹配（模板库+AI 生成降级），但**无音效匹配**。
- **建议方案**：新增 `sfxService.js`（音效素材库 + 场景标签匹配 + 插入时间点），在成片合成阶段叠加音效轨。

### P2-18 任务队列 Bull/Redis 化（8.1 性能优化）
- **需求描述**：任务队列建议使用 Bull/Redis 保证可靠性、断点续传、失败重试。
- **当前现状**：`queueService.js` 为**内存队列 + Semaphore 限流**（并发控制可靠，但进程重启任务丢失，无跨进程队列）。
- **建议方案**：内存队列已有断点续传/重试，可在 `config.yaml` 配置 Redis 后接入 Bull（渐进替换，保留内存降级）。

### P2-19 LoRA 训练集成（3.2 角色一致性）
- **需求描述**：专业版提供 LoRA 训练能力，训练后可一键注入。
- **当前现状**：仅 `promptI18n.js` 中作为提示词文案出现、会员等级文案提及"LoRA 训练"权益，**无任何真实训练任务/模型管理**。
- **建议方案**：属高成本能力，建议以"角色参考图（IP-Adapter/参考图锚定）+ 角色指纹"为已交付替代能力；LoRA 训练作为远期规划，先在下单页标注"训练中"或隐藏该项权益，避免承诺无法兑现。

## 五、已满足需求概览（验证已覆盖，作为检查底稿）

以下功能经代码走查确认为**完整实现**，不在本次开发范围内：

- **3.1 AI 编剧助手**：多轮对话、逐段修改/重新生成、剧本-角色-场景-分镜联动更新、长文本导入
- **3.3 智能分镜**：镜头类型/运镜/构图/情绪/时长/转场建议、参数调整重生成
- **3.5 风格统一引擎**：项目级风格配置（global_style/color_palette/line_weight/shading_style/composition_rule）、角色/场景覆盖
- **4.1 一站式工作台**：左侧项目导航树、右侧 AI 面板、底部时间轴预览
- **4.2 无限画布**：多层级缩放（compact/normal/detailed）、小地图、分区与智能布局、搜索（Cmd+F）、书签、标注（CanvasAnnotations）、节点虚拟化、图片懒加载、RAF 节流（**分支叙事除外**）
- **4.3 模板系统**：模板市场、按模板创建
- **4.4 智能工作流**：步骤依赖、条件分支（evaluateCondition）、人工审核暂停点、失败自动重试、断点续传
- **4.5 新手引导**：交互式引导、提示气泡、示例项目导入
- **5.1 团队协作**：WebSocket 实时同步（collaborationGateway）、操作锁定、协作通知
- **5.2 版本管理**：自动快照、版本对比、回退
- **6.1 智能标签**：五维度自动标签
- **6.2 素材推荐**：按场景/角色/情绪推荐、一键应用
- **6.3 跨项目复用**：项目/个人/团队三级素材库
- **7.2 配音同步**：时间轴对齐、时长匹配、多角色混音
- **8.2 对象存储**：StorageAdapter/MinIO、迁移工具、生命周期管理
- **8.3 数据分析（基础）**：用户/创作漏斗/模型效果/内容/财务统计
- **9.1 运营看板（基础）**：实时数据、AI 异常洞察、创作漏斗、模型成本看板
- **9.3 内容审核**：AI 图文视频审核、人工复审工作台、规则配置、违规拦截+通知、审核记录/申诉
- **9.4 用户生命周期**：画像、行为轨迹、阶段标记、流失预警、分群运营、健康分
- **9.6 系统监控（基础）**：健康大屏、API 监控、队列监控、智能告警（钉钉/企微/飞书）

## 六、遗留风险与建议

1. **管理端占位页容易被误判为"已上线"**：25 个占位页在路由中可达但无功能，建议在补齐前于菜单上隐藏或标注"开发中"，避免运营误操作。
2. **LoRA 训练承诺与实现不一致**：会员等级文案含"LoRA 训练"权益但无实现，存在合规/体验风险，建议先下架该权益文案或标记"敬请期待"。
3. **支付宝支付为占位实现**：`verifyAlipaySignature` 恒返回 false，若界面提示支持支付宝会产生误导，建议接入真实 SDK 或隐藏支付宝选项。
4. **埋点缺失影响运营决策**：留存分析、转化漏斗依赖埋点数据，建议优先补 P1-13 事件埋点，为运营看板提供数据源。
5. **数据导出合规**：P1-14 数据导出不仅服务运营，也是企业用户合规诉求（数据可带走），建议纳入 P1。
